1
Resumo simples do app

O que o app é, em uma respirada só.

O AgroVision é um aplicativo de celular que analisa uma foto de folha de milho, identifica se ela está doente (e qual doença), e depois mostra onde o modelo de IA olhou na imagem para tomar essa decisão — de forma visual, com um mapa de calor.

A grande pergunta do TCC não é "o app classifica doenças?" (isso qualquer modelo de IA faz). A pergunta é: "o modelo está olhando para o lugar certo?" — ou seja, a IA aprendeu a reconhecer a doença pela folha, ou por algum artefato de fundo que não faz sentido?

1 — Usuário fotografa a folha

App captura a foto pela câmera ou galeria.

2 — Classificação via Roboflow

A imagem vai pela internet até o servidor Roboflow, que retorna a classe prevista (Helmintosporiose, Ferrugem, Mancha-Cinzenta ou Saudável) e o percentual de confiança.

3 — Grad-CAM no servidor

O backend Python recalcula o Grad-CAM com o modelo Keras local (precisa dos gradientes, que o Roboflow não expõe). Resultado: mapa de calor mostrando onde o modelo se concentrou.

4 — Métricas AFS e AL (nossa intervenção)

O servidor calcula se a atenção do modelo está dentro ou fora da folha (ROI). Gera dois números: AFS (atenção no lugar certo) e AL (atenção vazada para o fundo).

5 — Resultado na tela

App mostra: doença detectada, confiança, mapa de calor colorido, AFS, AL e recomendações agrícolas.

2
Dor que o app resolve

Problema prático

Produtores rurais, especialmente pequenos e médios, não têm acesso rápido a um agrônomo para diagnosticar doenças em lavoura de milho. Um diagnóstico errado (tratar Ferrugem como Helmintosporiose, por exemplo) desperdiça dinheiro com fungicida errado e pode comprometer a safra inteira.

Problema científico (o mais relevante para o TCC)

Modelos de IA que classificam doenças em imagens existem há anos — mas ninguém garante que eles estejam olhando para o lugar biologicamente correto. Um modelo pode acertar a classe por reconhecer a cor do substrato da foto de laboratório, a régua usada na imagem, ou qualquer artefato que aparece sempre junto com a doença no dataset.

Sem uma métrica quantitativa, não há como distinguir um modelo que entendeu a biologia de um que memorizou detalhes do dataset. Essa é a lacuna que o TCC preenche.

3
Linguagem e tecnologia

O que está sendo usado e por quê.

React Native + Expo (TypeScript)
Aplicativo mobile. Roda em Android e iOS com um único código. Expo abstrai câmera, sistema de arquivos e armazenamento local.
Python + FastAPI
Backend na nuvem (Railway). Recebe a imagem pelo celular via WebSocket, processa Grad-CAM e calcula AFS/AL, devolve o resultado.
TensorFlow + Keras
Biblioteca de deep learning. Usada apenas no backend para calcular o Grad-CAM — precisa dos gradientes, que só existem com o modelo Keras completo.
Roboflow Serverless
Serviço de inferência na nuvem. Faz a classificação da doença. Retorna classe + confiança via API REST. Não expõe gradientes.
OpenCV + NumPy
Biblioteca de visão computacional. Usada para segmentação por cor (HSV), morfologia e sobreposição do mapa de calor na imagem.
SQLite (expo-sqlite)
Banco de dados local no celular. Guarda o histórico de diagnósticos para o usuário consultar offline.
Por que dois serviços separados (Roboflow + backend próprio)?
Roboflow classifica com eficiência mas é uma caixa-preta — não devolve os pesos intermediários nem gradientes. Para o Grad-CAM é preciso acesso completo ao grafo computacional do modelo. Por isso o modelo Keras fica no nosso servidor e é usado exclusivamente para gerar a explicação visual.
4
Algoritmos — autores, o que fazem, resultado

Cada algoritmo que o sistema usa, de onde veio e o que produz.

Classificação
🧠

MobileNetV2

Howard et al., 2018 — Google Brain · MobileNetV2: Inverted Residuals and Linear Bottlenecks
O que é Rede neural convolucional profunda (CNN) projetada para dispositivos com recursos limitados, como celulares. Usa convoluções separáveis em profundidade para ser leve.
O que faz aqui É a espinha dorsal do modelo de classificação. Recebe a imagem (224×224 pixels) e extrai 1.280 características na última camada convolucional (Conv_1). Essas características são o que o Grad-CAM usa.
Resultado Probabilidade para cada uma das 4 classes de doença. A classe com maior probabilidade é a previsão final.
Transfer learning O modelo foi pré-treinado no ImageNet (1,2 milhões de imagens gerais) e depois re-treinado (fine-tuning) com imagens de folhas de milho doentes.
Explicabilidade
🗺️

Grad-CAM — Gradient-weighted Class Activation Mapping

Selvaraju et al., 2017 — "Grad-CAM: Visual Explanations from Deep Networks via Gradient-based Localization" · ICCV 2017
O que é Método de XAI (Explicabilidade de IA) que mostra visualmente quais regiões da imagem a rede neural usou para tomar sua decisão.
Como funciona Calcula o gradiente da pontuação da classe prevista em relação aos mapas de ativação da última camada convolucional. Faz a média global desses gradientes por canal → pesos de importância. Multiplica cada mapa de ativação pelo seu peso e soma tudo → mapa de calor. Aplica ReLU (zera negativos) e normaliza para [0, 1].
Resultado Imagem em escala de calor (0 = sem atenção, 1 = máxima atenção) no mesmo tamanho da imagem original, mostrando onde o modelo "olhou".
Por que a última conv? Camadas convolucionais finais têm resolução espacial suficiente para localizar regiões na imagem e ainda contêm informação semântica sobre a classe.
Segmentação
🎨

Segmentação por cor HSV + Morfologia + Componentes Conectados

Técnicas clássicas de Visão Computacional · implementadas com OpenCV (Bradski, 2000)
O que é Pipeline de três etapas para encontrar automaticamente a região de interesse (a folha verde) na imagem, sem anotação manual.
HSV Converte a imagem de RGB para o espaço de cor HSV (Matiz, Saturação, Valor). Nesse espaço é muito mais fácil isolar "verde" com um range de thresholds: Matiz 25–95°, Saturação e Valor mínimos para evitar capturar cinza ou branco.
Morfologia Abertura (remove ruído pequeno) + Fechamento (preenche buracos) com kernel elíptico 5×5. Limpa a máscara binária gerada pelo threshold HSV.
Componentes Conectados Encontra todos os "blobs" de verde na máscara. Seleciona o maior (que é a folha). Extrai seu bounding box (x, y, largura, altura).
Resultado Máscara binária (0 e 1) do mesmo tamanho da imagem, com 1 dentro do bounding box da folha e 0 fora. Essa máscara é o ROI (Região de Interesse) usado nas métricas.
5
Intervenção científica — o que inventamos e por quê

Esta é a contribuição original do TCC. O que não existia antes e que nosso trabalho propõe.

Por que isso era necessário?
O Grad-CAM gera um mapa de calor visual — mas visual não é suficiente para a ciência. Precisamos de um número que responda: "quanto da atenção do modelo caiu dentro da folha?". Sem número não há comparação entre modelos, não há experimento repetível, não há conclusão científica robusta.
Por que não usar métricas existentes?
As métricas mais conhecidas (Pointing Game, RISE, ROAD) exigem anotação manual de segmentos por pixel ou são computacionalmente muito caras. Nossa proposta usa a própria cor da folha (verde) como segmentação automática — zero anotação humana, aplicável a qualquer imagem de lavoura em campo.

As duas métricas que criamos

⚡

AL — Attention Leakage (Vazamento de Atenção)

Métrica original — AgroVision TCC, 2024

Mede a fração da atenção do modelo que "vazou" para fora da região de interesse (a folha). Um AL alto significa que o modelo está olhando para o fundo, não para a planta.

# Passo 1: aplicar threshold (eliminar atenção de baixa intensidade / ruído) active = pixels do heatmap com valor ≥ threshold (padrão: 0,5) # Passo 2: separar atenção dentro e fora da máscara inside = Σ(active × mask) # atenção dentro da folha outside = Σ(active × (1 − mask)) # atenção fora da folha (fundo) total = inside + outside # Passo 3: calcular AL AL = outside / total # vai de 0 (nenhum vazamento) a 1 (tudo fora)
🎯

AFS — Attention Focus Score (Pontuação de Foco de Atenção)

Métrica original — AgroVision TCC, 2024

O complemento direto do AL. Mede quanto da atenção está no lugar certo (dentro da folha). AFS = 1 significa atenção perfeita; AFS = 0 significa que o modelo ignorou completamente a folha.

AFS = 1 − AL # Exemplos de interpretação: AFS = 0,92 → 92% da atenção está na folha → Excelente AFS = 0,65 → 65% na folha, 35% no fundo → Suspeito AFS = 0,40 → modelo olhando mais pro fundo → Problemático

Lógica de escolha do threshold = 0,5

O heatmap Grad-CAM é normalizado entre 0 e 1. Regiões com valor abaixo de 0,5 representam atenção fraca — ruído estatístico da rede, não foco real. Ao zerar esses pixels antes de calcular o AL/AFS, evitamos que ruído de fundo distorça a métrica. O valor 0,5 é configurável via parâmetro da API e pode ser ajustado para experimentos de sensibilidade.

Como isso influencia o TCC

As métricas AFS/AL permitem responder com número às três perguntas de pesquisa do TCC:

  1. O modelo está olhando para a região biologicamente correta? → AFS médio por classe
  2. A confiança alta do modelo correlaciona com atenção correta? → correlação confiança × AFS
  3. Qual estratégia de máscara (automática por cor vs. fixada centralizada) produz métricas mais estáveis? → comparação experimental

Onde está o TCC no código

Se o professor perguntar "onde isso está no app?" — use esta tabela.

Backend Python — Intervenção científica (núcleo do TCC)
api/xai/metrics.py
Cálculo de AL e AFS. Intervenção
Funções compute_attention_leakage(). Recebe o heatmap e a máscara binária, aplica threshold, separa atenção dentro/fora e retorna o dataclass AttentionMetrics com al, afs, inside_sum, outside_sum, total_sum.
api/xai/mask.py
Geração automática do ROI (máscara da folha). Intervenção
Função green_segmentation_bbox(): HSV threshold → morfologia (opening + closing) → componentes conectados → bounding box da maior blob verde.
Função fixed_center_bbox(): fallback centralizado quando não encontra verde suficiente.
Função create_mask_from_bbox(): converte o bbox em máscara binária (H×W).
api/xai/gradcam.py
Implementação do Grad-CAM (Selvaraju et al., 2017). Algoritmo
Função generate_gradcam(): constrói sub-modelo que expõe mapas de ativação, usa GradientTape para calcular gradientes, faz global average pooling dos gradientes, combina com mapas de ativação, aplica ReLU e normaliza.
api/xai/roboflow.py
Proxy de classificação — Roboflow Serverless API.
Função classify(): redimensiona a imagem, envia como base64 para a API Roboflow e normaliza a resposta para o formato interno do sistema.
api/xai/model_loader.py
Singleton do modelo Keras em memória.
Classe ModelRegistry: carrega o model_species.keras uma vez no startup e mantém na RAM para todos os requests de Grad-CAM. Também lê os labels do labels_species.json.
api/server.py
Endpoints WebSocket que orquestram tudo.
ws_classify: recebe imagem → Roboflow → retorna classe + confiança.
ws_gradcam: recebe imagem → Grad-CAM → máscara → AL/AFS → overlay → retorna tudo.
_gradcam_sync(): função síncrona que executa toda a cadeia de cálculo no threadpool.
model_species.keras
Arquivo do modelo treinado.
MobileNetV2 com fine-tuning para as 4 classes de milho. Usado exclusivamente para Grad-CAM — a classificação em produção usa o Roboflow.
labels_species.json
Mapeamento índice → nome de classe.
Ex.: {"0": "Blight", "1": "Common_Rust", "2": "Gray_Leaf_Spot", "3": "Healthy"}. Necessário para o Grad-CAM saber qual neurônio de saída usar quando a classe é fornecida por nome.
App Mobile (TypeScript) — Interface e chamadas
src/services/ml/xaiService.ts
Chamada WebSocket para o Grad-CAM + AL/AFS.
Abre conexão ws_gradcam, envia imagem + parâmetros (strategy, threshold, coverage), recebe eventos de progresso em tempo real e o resultado final com AFS, AL, overlay_b64, heatmap_b64.
src/services/ml/classifyService.ts
Chamada WebSocket para classificação via Roboflow.
Abre ws_classify, envia imagem em base64, recebe classe + confiança. Mapeia as classes do modelo para descrições em português e recomendações agrícolas.
src/screens/ResultScreen.tsx
Tela que exibe os resultados para o usuário.
Mostra: classe prevista, confiança, mapa de calor (overlay), AFS e AL com barra visual, recomendações agrícolas e metadados técnicos (camada conv usada, tempo de processamento).
src/services/storage/database.ts
Persistência local com SQLite.
Salva cada diagnóstico no banco de dados do celular: id, timestamp, classe, confiança, AFS, AL, URI da imagem. Permite histórico offline.
Dica para apresentação: Se o professor pedir para mostrar o cálculo do AFS ao vivo, abra agrovision-ml-service/api/xai/metrics.py — são menos de 30 linhas e a lógica está toda ali, comentada. É o coração matemático do TCC.

Objetivo técnico-científico

Desenvolver e validar uma metodologia quantitativa — baseada em métricas originais (AFS e AL) calculadas sobre mapas de ativação Grad-CAM — que permite avaliar se um modelo de deep learning está utilizando regiões semanticamente relevantes da imagem (a folha da planta) ao classificar doenças foliares de milho.

Objetivo prático

Entregar um aplicativo funcional que um produtor rural possa usar no campo: fotografa a folha, recebe diagnóstico imediato da doença com recomendação agrícola, e vê visualmente para onde a IA estava "olhando" — aumentando a confiança e transparência do resultado.
